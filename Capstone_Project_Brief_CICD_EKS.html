Student Mission Statement:
In the preceding phase of this capstone, you manually provisioned a hardened 3-tier retail microservices architecture on Amazon EKS—incorporating Terraform IaaS, Karpenter Spot autoscaling, External Secrets Operator, and AWS Load Balancer Controller.

Your next critical objective is complete operational automation. You must design, implement, and validate an enterprise-grade, keyless CI/CD pipeline using GitHub Actions that automates software quality gates, container packaging to Amazon ECR, zero-downtime rolling updates to Amazon EKS, and post-deployment smoke testing.

1. Executive Project Overview

Modern platform engineering mandates that zero manual deployments occur in production environments. All code changes—from application logic to infrastructure manifests—must flow through an automated delivery pipeline that tests, verifies, builds, scans, and deploys without human intervention.

This project brief tasks you with building an end-to-end Continuous Integration and Continuous Deployment (CI/CD) system for the Cloud Retail platform.

High-Level Architectural Flow

Developer Commit / Pull Request
             │
             ▼
   [ GitHub Actions CI Gate ]
   ├── Linting (Flake8 / ESLint)
   ├── Automated Unit Tests (Pytest)

   [ GitHub Actions CD Delivery ]

   ├── Push to Amazon ECR with Immutable Git SHA Tags
   ├── Rolling Update Deployment to Amazon EKS (kubectl set image)
   ├── Rollout Verification (kubectl rollout status)
   └── Automated Smoke Test against Live AWS Application Load Balancer

2. Core Learning & Engineering Objectives

Upon completing this project, students must demonstrate production competency in:

  1. Keyless Cloud Authentication: Eliminating long-lived static AWS access keys by configuring AWS IAM OpenID Connect (OIDC) federation with GitHub Actions.
  2. Multi-Tier Continuous Integration: Building automated quality gates that reject faulty Python, TypeScript/React, Terraform, or Kubernetes code before merging.
  3. Multi-Architecture Container Packaging: Creating optimized, reproducible Docker multi-stage builds targeted at linux/amd64 with GitHub Actions caching to minimize build latency.
  4. Immutable Artifact Release Engineering: Tagging and deploying container images using Git commit SHAs (${{ github.sha }}) to guarantee total traceability.
  5. Zero-Downtime Kubernetes Deployments: Implementing automated rolling updates on Amazon EKS with progress deadlines and automated failure detection.
  6. Automated Platform Smoke Testing: Validating live ingress endpoints (HTTP 200 OK, database connectivity, catalog queries) via pipeline execution.

3. Detailed Scope of Work & Technical Milestones

Milestone 1: Automated Quality Gate (CI Workflow)

Create a dedicated pull-request validation workflow located at .github/workflows/ci.yaml that triggers on any pull request targeting the main branch. The workflow must execute four concurrent or sequential jobs:

  • Backend Quality Gate: Sets up Python 3.11, installs application dependencies, executes syntax/lint checks via flake8, and runs automated unit/health tests using pytest.
  • Frontend Quality Gate: Sets up Node.js 20, runs clean dependency installation (npm ci), and validates that the React SPA bundle compiles without errors (npm run build).
  • Infrastructure Quality Gate: Runs terraform fmt -check and terraform validate in the infrastructure/ directory.
  • Kubernetes Manifest Gate: Performs client-side dry-run validation (kubectl apply --dry-run=client) across all manifests in manifests/.

Milestone 2: Keyless AWS OIDC IAM Infrastructure

Hardcoding AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY into GitHub Repository Secrets is strictly prohibited. You must configure keyless OpenID Connect (OIDC) identity federation in Terraform (infrastructure/github_oidc.tf):

  • Establish an AWS IAM OIDC Provider for token.actions.githubusercontent.com with audience sts.amazonaws.com.
  • Provision an IAM Role (cloud-retail-github-actions-role) with an sts:AssumeRoleWithWebIdentity trust policy strictly locked down to your GitHub repository: 
    StringEquals:
  token.actions.githubusercontent.com:aud: "sts.amazonaws.com"
StringLike:
  token.actions.githubusercontent.com:sub: "repo:YOUR_GITHUB_ORG/YOUR_REPO:*"
  • Attach fine-grained policies allowing ECR push/pull for retail-frontend and retail-backend, and eks:DescribeCluster for cloud-retail-eks.
  • Create an EKS Access Entry linking the GitHub Actions IAM role to Kubernetes RBAC to permit deployment rollouts.

Milestone 3: Automated Continuous Deployment (CD Workflow)

Create a deployment workflow at .github/workflows/cd.yaml that triggers automatically on any push or merge to the main branch:

  • Job 1: Build & Push to Amazon ECR:
    • Uses aws-actions/configure-aws-credentials@v4 with role-to-assume (OIDC).
    • Uses Docker Buildx with GitHub Actions caching (type=gha).
    • Builds both backend-api and frontend-ui images for --platform linux/amd64.
    • Pushes images to ECR tagged with both :latest and :${{ github.sha }}.
  • Job 2: Zero-Downtime EKS Deployment & Smoke Test:
    • Configures cluster authentication via aws eks update-kubeconfig.
    • Updates the active Kubernetes Deployments with the newly minted Git SHA image tag.
    • Waits for both rollouts using kubectl rollout status with explicit timeouts.
    • Extracts the public Application Load Balancer DNS address from retail-frontend-ingress.
    • Executes live automated curl tests against /api/health and /api/products, failing the pipeline if the HTTP status code is not 200 or the database connection is offline.
FinOps Alert:
Ensure your pipeline leverages GitHub Actions cache (cache-from: type=gha) to avoid rebuilding intermediate Docker layers on every commit. This reduces CI/CD runtime from 8+ minutes to under 90 seconds.
